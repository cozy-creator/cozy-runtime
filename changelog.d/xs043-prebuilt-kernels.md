Prebuilt kernels (xs-043 K). Runtime's native wheels (Linux x86_64 and aarch64, Windows x86_64; cp312-abi3) carry its compiled CUDA kernels under `cozy_runtime/_kernels`: every GPU target's cubins plus PTX, nanobind on the stable ABI, no torch ABI. The pure wheel carries none. The 8-bit op (int8/fp8 GEMMs, quantize, GEMV) and FlashAttention-3's forward serve once they pass `verify_op` on the card: a probe against the float64 law, kept per machine by (kernel, artifact, arch, driver); a kernel that fails, or ends its process, is refused, and the run says so once. Every compiled attention kernel is verified the same way. Linux aarch64 carries no FA3 (cr-200); Windows carries int8 mma.sync GEMMs only, and a run's GEMM column names the kernel that served and why (cr-201). The driver leaves every compile key. `kernels.yaml` builds the modules into a cache keyed by everything that shapes their bytes: a release with unchanged `kernels/` only repackages. Deleted: the boot-compiled 8-bit torch op (`int8_op/op.cpp`, `setup.py`, recipe `cozy-int8`), its boot build and family inheritance by build (§2.6 now takes the first family whose prebuilt kernels verify), the trimmed FA3 recipe with its text patches (a Hopper card whose prebuilt FA3 fails builds `flash-attn3-full`), and the `_C` native path: RMSNorm + split-half RoPE is `cozy_runtime._kernels._norm` (`author.kernels.native()` says when the wheel carries none), Runtime builds with plain hatchling (no 0.18.86 donor, `build-kernel-wheel.sh`, `build-dev-wheel.py` or root CMakeLists).
