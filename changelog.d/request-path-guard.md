A run names the kernel work that blocked it. A compile, tune, self-check, build wait or CUDA graph capture that runs on the request's own thread is the run's `request_path.blocking` confession (value: the work, e.g. `kernel self-check: prebuilt-w4a8`, `kernel build wait: lora bake`, `triton compile: <kernel>`; fields `ms`, `times`), plus one warning, "kernel work blocked the request". It never fails the run. Work on another thread is not one: a run starts on a ready kernel while better ones build in the background. Graph capture in `graphs` and LM decode is the one named exception (cr-210) and records nothing. CI fails on any new compile, tune or capture call outside the guard.
