An LM decode graph's check saves only what its step can write: the decode state, and each key buffer at the few positions a step reaches in each row, never the buffer (cr-333). Since cr-283 it cloned every key and value buffer whole, the decode cache again (10 GiB at 16 rows of Qwen3.8-27B), and the capture's write set stayed referenced after the check, so a call that regrew its slots allocated them beside the last call's: MiniMax-H3-Image's expander failed its second call in an executor with `device_fault` on a 48 GB and an 80 GB card. The snapshot and the write set now go when the check ends, and what a step writes on the host is never put back.
