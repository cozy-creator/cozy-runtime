A construction's one-card view of `torch.cuda` (D3) answers package code only, decided per call by its nearest Runtime frame: the Runtime's own probes, other threads (a group's kernels, residency, TensorFS) and torch's `get_device_properties` reached from them always see the real cards (cr-335, hack audit #6; cr-326 was this). A model's fill and registration (`materialize`, `fill`, `commit`: weights registered with memory, derived buffers placed, encoded leaves installed) run once the package's `load()` has returned, outside the construction, so `derive.placing()` and its escape are gone.
