`@app.entrypoint` and `@app.tool` take `needs={"slot": "<CEL>"}` (cl-1103): one CEL boolean expression over `request` per model argument, read from source into the interface (`models[].needs`). The machine fetches a model before the function starts only for the requests its rule is true for, and never for the others; the argument is built when the function first reads it, as an `on_demand` one is (the interface says `on_demand` too, for a reader that evaluates no rule). In a function that loads no model and calls others, a key names a function it calls (`calls[].needs`). `Context.need(slot)` asks for a deferred model's weights mid-run: they come first in every download while the function goes on.
