A stage whose room makes torch drop its whole cache more than once in an entry gets more before its next one: components no stage uses then leave the device, the cheapest to restore first (bytes mapped from the machine's custody are given back to it), and fill again when their own stage opens. The room that squeezed is reported (`squeezed`) and seeded into later executors (`Invoke.squeezed_bytes`), which page before their first entry. Under a per-process limit torch refuses a request when its reserved bytes plus the request pass the limit, even one that only extends a block it holds, so a peak that fits still squeezes: H3 at 362 frames on an RTX PRO 6000 with every component mapped ran each denoise step 3–5 s slower with 371 cache drops in a call (run 4397).
