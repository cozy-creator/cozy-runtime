The package contract forbids only harm to the process a package shares, never a shape of code. Describe and the executor's seal no longer judge direct attention calls (`F.scaled_dot_product_attention`, flash-attn, xformers), `threading.Thread` and thread pools, host reads (`.item()`, `.cpu()`, `.tolist()`), library decode (`model.generate`, `DynamicCache`, `use_cache=True`), or a read of capture state. `cozy_runtime`'s modules are the author's to import except `internal`, `graphs`, `cli` and private names. Still refused: `weights_io`, `process`, `env_write`, `global_flag`, `global_rng`, `allocator`, `room_query`, `oom_catch`, `internal_import`, `own_stream` (streams, graphs, `synchronize`, `set_device`) and `compile`. A refusal names its rule and the harm: `torch.cuda.empty_cache is not allowed in a package (allocator, model.py:12): the allocator is varena's, which reclaims on its own`.

The seal no longer blames a package for what a library does on its own: a library's module body (an env default or helper process at import), a library reading a file of its own installed tree, `torch.cuda.current_stream()` wrapping the stream that exists, and numerics flags a library's import moved (put back and logged, not refused). A library's call made for the package is still the package's, and its refusal names the library (`, via <library>`). A package thread is a run warning (`contract_thread`) only when it runs a component.
