The memory's catch and cuts (xs-046 B3, `tensorfs.varena.cuts`). An op that runs out of device memory runs again in a strictly smaller configuration: rungs 1-2, the cut around it finer, its own bands, rung 4, else `memory_exhausted`. Attention through the Runtime's dispatch cuts by head groups then query rows at the kernel's block; a package's `split` runs whole, else in the windows that fit, the size remembered per op (`per_element` is gone). Deleted: `bands.py` (and the encoded linears' row cuts), `spill.py` (mapped, out and disk tiers; `graphs.native`). A package declares what its forward changes outside a block as `_cozy_state` (attribute paths under the component's root); it is put back before a block that ran out of memory runs again.
