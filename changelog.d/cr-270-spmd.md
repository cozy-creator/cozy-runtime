A multi-GPU package's handler runs on every GPU, as ordinary PyTorch multi-GPU code does: the same request, seeds and random streams on each, sharded components split and gathered inside their own calls (Diffusers' context-parallel hooks), so a plain loop is correct on one GPU or eight with no rule to learn. The reply, outputs and progress are GPU 0's; the other GPUs save nothing. One GPU failing or reaching a different call ends the attempt on all of them with its own error, and the group serves the next request. `concurrently` runs its calls in order; `spread`'s `spare` has no effect.
