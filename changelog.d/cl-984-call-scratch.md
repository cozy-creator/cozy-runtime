An executor runs each Invoke in the folder TensorD names with it (`scratch`, inside the call's project): its temporary files, working directory, HOME and stdout/stderr are there while it runs, and `work/`, `tmp/` and `home/` go when it ends, so one executor serves several projects' calls with each one's files in its own project. A lookahead preparation's prints wait for its own call's log. `Invoke.store` names the store for the call's own checkpoints. No `scratch`: as before (cl-984).
