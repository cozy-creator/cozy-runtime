A native kernel's self-check no longer turns it off on a machine (fix for 0.30.10). Since 0.30.10 the prebuilt 8-bit op first opens at a leaf's bind, inside its model's construction, where the construction guard refused the probe's device pin; the failure was kept per machine and the op stayed off there (comfy-kitchen or `_int_mm` served). The probe now runs with the guard stepped aside, and a verdict, pass or fail, lives only in its process: a failure serves the next kernel and the run says so (`gemm.fallback`), and the next process checks again. The one thing a machine keeps is a probe that ended its process (the crash-loop guard), keyed by the Runtime build, so an upgrade checks it again; verdicts 0.30.10 kept are never read.
