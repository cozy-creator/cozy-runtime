A missing optional build tool never fails a run (owner rule 2026-10-17). Runtime looks for `nvcc` (PATH, else `CUDA_HOME/bin`), the C/C++ compiler (`cc`: `CXX`/`c++` for a recipe build, `CC`/gcc/clang for Triton) and `ninja` before a build starts. A build that cannot run never starts and its fallback serves (SDPA or the next attention kernel, eager GEMMs, eager LoRA bake, eager fp8 quantize); without `ninja` the build runs one file at a time. Every run of that process then carries one warning per missing tool, `<tool> not found: <cost>; see `cozy doctor``, with cozy's cost text (`cozy_platform::tools`) and fields `code` (`kernel_prebuilt_missing`, `kernel_verify_failed` or `triton_no_compiler`) and `tool`. It never quotes the compiler's error.
