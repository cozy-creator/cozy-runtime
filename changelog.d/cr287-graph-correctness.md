CUDA graph correctness (tracker design cuda-graph-correctness.md; cr-287, cr-300, cr-283):
- An idle recording is a call's recording, run later: on its call's own inputs (kept on pinned host memory when its signature is queued, up to 128 MiB, else only a call records it), the call as written first with its device reads answering the capture's, and the check against that run, bit for bit. Invented inputs failed both ways: zero indices made P-H3-Image's `index_copy_` race (`replay_mismatch` in all 786432 values, H100 47107, rtx-5090 gate 44045774883), and a zero mask let Anima's encoder graph pass and serve other bytes (cr-300). cr-300's hold on 2-D integer inputs is gone: text encoders record at idle again.
- A replay that differs explains itself, once per key: the call as written runs again from where it started, and the record names "the call as written differs run to run" (a nondeterministic kernel) or "the capture ran another program" with the first op that differs, a kernel landing, attention's backends or split levels. The LM decode check does the same, and runs the step on its capture's stream too.
- A dev machine (`dev = true` in its config.toml, sent in the executor's `Start`) audits every 16th replay of a region against the call as written, as `FORCE` builds did.
