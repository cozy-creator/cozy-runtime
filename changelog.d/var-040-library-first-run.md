Each call tells TensorFS its code path (its function and the names of the inputs it gave) and whether it completed, so a path's first run in a process keeps room on the card for the libraries it loads (an LTX-2.5 retake's first cuFFT plan failed with `CUFFT_INTERNAL_ERROR` on a full 4090 after a text-to-video in the same process). When a Runtime-owned op's library or the driver still refuses its own allocation by its out-of-memory code, TensorFS frees room from idle memory and the op runs once more (var-040).
