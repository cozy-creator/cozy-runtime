A component's CUDA graph is recorded in its call at the path's second sight (cr-297), and four things about that are tightened. An argument or a host object in a path's key is no longer keyed by a Python `id`: an object is keyed by a number of its own that no later object at its address can take, a number-like value (a numpy scalar, a small array, a `slice`) by its value, a long or deep list, tuple or dict by its items, and one too long to read runs its call as written. A path records only after a call as written that changed neither its arguments nor the host state its key reads, since a capture runs the forward's Python once more; and whatever a recording binds or changes on a module (a tensor, a public list or dict, a new attribute, as well as a plain value) is put back, and a changed list, dict or plain value leaves the path as written. A region whose paths changed every request stopped recording for the process: it records again once a path of an earlier request comes back or an earlier graph replays. `graphs.FORCE` (gate builds) no longer raises after each capture that succeeds.
