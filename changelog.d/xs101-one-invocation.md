One invocation driver (xs-101). `invoke_with_fakes` builds an `Invocation` and runs `prepare` then `run_prepared`, as the executor does, and returns the same `(result, outcome, attempt)`; `author.attempt` and the public `invoke` are gone. `Invocation` and `prepare` drop what no production path supplies (`settings`, `secrets`, `default_sets`, `clamps`, `adapters`, `egress_broker`); LoRA adapters ride the model. `Settings[T]` and `Secrets[S]` join `Egress` as ungrantable: publish and install refuse them (`ungrantable_capability`) instead of every request refusing with `settings_invalid`.
