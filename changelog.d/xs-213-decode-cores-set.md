The decode cores' Triton kernels are declared Runtime kernel sets, one per scheme (`cozy-decode-<scheme>`, xs-213): a scheme row traced through the cores at each listed param, optional parts and destination dtype (`cozy-decode-ggml.q8_0` holds 3 entries, the largest 48). A load names the schemes it decodes with and their sets build beside its fill; a first ask builds one nothing named. A set serves once each entry decodes bit for bit as the reference. A decode never compiles: until its set serves, and for a call it does not hold, the reference decodes on the host and is copied in. Each attempt records the decodes per scheme and path (`kernel.decode_cores`: `set`, `host` or `device`). ggml's struct kernel takes its struct as an integer `FORM` in place of a function constexpr.
