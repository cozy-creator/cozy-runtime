A request's attention pin is honoured on every load and request. TensorD sends the first request's pin with Load (`attention.load_pin/1`), so its kernel build is imported before default selection; a build that also holds the default kernel (`flash-attn3-full`, `sageattention-full`) serves both. A later pin needing another build refuses with `attention_kernel_needs_executor` and TensorD runs it on a fresh executor. A pin falls back only where its kernel cannot run (card, shape, group degree, failed build, compiled module), and `cozy run show` names the fallback and why. Load no longer installs a construction pin.
