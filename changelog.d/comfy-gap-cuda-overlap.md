An executor's GPU comes up on its own thread: Start replies at once, and construction reads its package and checkpoint headers meanwhile, awaiting the device at its first device step. The GPU libraries' first launches run beside the construction. A package that touches `torch.cuda` early waits for the device instead of being refused, and a device that cannot start (`device_out_of_memory`) is refused at that first step. The run record's executor legs split `cuda_init` into `activate`, `torch`, `memory`, `ready` and `first_launches`.
