Ordinary PyTorch works in a package. Calls that mean nothing under the Runtime do nothing, with one run warning per kind: `torch.compile` (returns the module), `nn.Module.compile`, `torch.cuda.empty_cache` and the memory-stat resets, memory fractions, `make_graphed_callables` (returns its callables), SDPA backend choices, `cudnn.benchmark = True`, a new `torch.cuda.Stream()` (the current stream), and a switch to another device or stream. Calls that mean something for one request are scoped to it: `torch.manual_seed`, `torch.cuda.manual_seed(_all)`, `fork_rng`, `random.seed` and `numpy.random.seed` seed that request's own streams (its draws match a plain script's, whatever runs beside it), and numerics flags (`torch.backends.*`, `set_float32_matmul_precision`, `use_deterministic_algorithms`, default dtype and device) apply inside that request's model calls and are put back after; one set at import or in `load` is the package's for every model call. `random.*` and `numpy.random.*` draws, CUDA generators and CUDA events are allowed. An environment write passes with one run warning per name, unless it would steer the Runtime or another request (`CUDA_*`, `NCCL_*`, `PYTORCH_*`, `TORCH_*`, compile caches, `HF_HUB_*` and offline settings, `COZY_*`, `TENSORFS_*`, and every name TensorD seals). Still refused, each in one line saying what to do instead: those environment writes, catching OOM, reading free memory, replacing the allocator, raw CUDA graphs, subprocesses, reading weight files, importing Runtime internals.
