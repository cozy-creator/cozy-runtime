A keyed `denoise_loop` call's first call records its whole program after its eager first step and runs the rest natively from it, so the next call runs natively however soon it comes (xs-134 F2; SDXL 1024 int8 on an RTX 4090: cold 7.8 → 6.8 s, the first warm call sent as cold settles 3.45 → 2.1 s). Every scope model is held and loaded first, since `after` has not run. Refused, the rest runs eagerly and the recording queues for the idle period as before. A plan finds what its graph reads from outside it by sorted byte spans instead of a scan of each held tensor against each output (SDXL's plan 320 → 5 ms on that card). The row names the recording's parts (`parts_ms`: load, bind, record_step, record_after, record_before, plan_held, plan_native, finish).
