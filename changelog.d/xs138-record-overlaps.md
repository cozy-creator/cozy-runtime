A first call's recording overlaps its eager steps instead of waiting for them: the eager steps before a recording return queued, a recorded graph's end no longer synchronizes, and the latents' finite check reads each step's sums from pinned host memory behind an event, one step behind, so an eager step no longer waits for itself and a native run's submission waits on nothing. The eager steps' own check is read once the call waits for its result. A loop with a LoRA overlay hook (`lora.Hook`) records when no overlay is armed as it records (the base forward); one armed then refuses. Overlays are armed before `denoise_loop`: those armed when it begins are part of its program's identity, so a program serves only calls that armed the same, and an overlay a step arms raises, eager or not ("arm overlays before denoise_loop").
