Model loading no longer writes checkpoint assets to disk. `ModelAssets.materialized` is removed; loaders read asset bytes with `read`/`open` and build path-only objects from them in memory (sdxl 2.3.15 builds its CLIP tokenizers this way). Before this change, preparing a model whose `load` materialized assets, such as paul/sdxl/generate, failed with `no_filesystem_writes` inside the derive sandbox.
