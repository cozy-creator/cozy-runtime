A `needs=` key may name a component of a Model argument, `<argument>.<component>` (`needs={"model.vision": "size(request.images) > 0"}`): where its rule is false the machine doesn't fetch that component for the call; the interface row carries it as the slot's `component_needs`. `vlm.construct` reads a Qwen3.5 checkpoint in either layout: one that stores the vision tower and the multi-token-prediction head as their own components (`vision`, `mtp`, as ingest now stores it) gets them as parts of the model it returns, each loaded and placed as its own component (`_loader.PARTS`), so a holder that names only `model` takes either. `vlm.VisionLM` refuses a Qwen3.5 checkpoint stored before the split (`checkpoint_layout`: upload its source again), and its `ask` names no `@uses_components`, so a slot fetches every component its checkpoint holds, less what its rules leave out (xs-213).
