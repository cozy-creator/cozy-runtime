`upload_checkpoint` no longer fails or wedges on transient R2/Hub errors or on Hub's asynchronous finalize. Opening, granting and pushing only stage bytes, so a failure before finalize retries the same frozen operation with backoff (Hub re-grants only objects it does not hold); it refuses, releasing the model hold, only on a Hub refusal or when ten consecutive attempts land nothing new. Only finalize marks the call sent, and a sent finalize is settled from Hub's durable finalization status (pending while queued/running, acknowledged when completed, refused only when Hub reports the job failed), never from the public checkpoint read that a private checkpoint answers with 404. A canceled parent releases an uncommitted upload's hold.
