# Native phase-region intent (stage1)

Request.plan/resolve already declares component phases; Memory._activate_phase now
only resets native preference metadata. This change will pass exact native Region
intent to Varena, so complete-operation choices can account for all phase weights,
not only those currently resident. Python supplies identity/order/actual regions,
never a window, reserve estimate or retained prefix.

Inventory is metadata-only. Reserve stable addresses as needed, but do not read or
pin every block to prepare a plan. Preserve common/tied identity, actual raw/final
representations and source/overlay/layout invalidation. Unknown/incomplete phases
remain unplanned. Initial native support is one arena per GPU; cross-arena ordering
is explicitly outside the bounded contract.

Working phase keys remain unknown until actual completion; this stage does not
claim eager-prefetch eligibility. Stage2 needs an optional immutable author-supplied
ordered inventory of supported typed consumers on denoise_loop, with metadata
preparation separate from actual per-call weight binding. No callback registry,
last-pass closure inference or guessed active key will be added.
