# Host admission for synchronous staging

Managed Executor fills obtain staging capacity from the existing Planner/Machine host-credit path before allocating buffers. The Planner can lower the slot count to one existing slot quantum; fill never expands admitted geometry. One slot drains each native batch synchronously. Arbitrary CUDA errors are propagated rather than treated as a host-pinning shortage.

A backend retains one fixed ring, reused across its fills. Each transaction establishes a fresh compute-to-copy dependency, then retains the current native/copy fences. This change does not overlap model computation with copying. Exact allocated, pinned and pageable staging bytes are reported separately in host memory; the retained buffers are included in managed host bytes. Idle host reclamation can drop the ring, but only fresh process/cgroup observations can establish physical relief: Torch's pinned allocator may retain its cache.

Single-rank admission holds its pending reservation through construction and native/copy drain. Once the ring exists, later fills reuse the same physical backing without another promise. Group operation preparation advertises the minimum unbacked quantum and consumes prepaid rank credit once; it never refunds credit based on a presumed pinned-cache release. Construction plan offers carry rank-local geometry separately from invariant plan equality. The leader reserves the aggregate before broadcasting agreement. Each group rank then physically materializes its fixed ring even when all model weights remain parked; broad warm scopes can reuse it before mirrored operation readiness. Single-rank staging remains lazy. An older follower's shared Load binding requires its full geometry because it cannot consume an additive reduced allowance. A newer follower refuses an absent applicable staging credit rather than allocate without authority.

Construction reservation ownership spans all follower fill replies and ends after verified drains, before group installation or authored warm can request operation credit. An asymmetric failure uses the existing group-close/reap boundary before releasing credit; unproved cleanup retains credit until Worker generation retirement. Failed DMA drains also retain the StoreRead gate and strongly owned backend/ring/read leases. The host executor holds first-construction backends before native filling, so losing a local registry or traceback cannot destroy pending DMA storage. This ownership is released only after a proven drain; a poisoned generation cannot resume allocation.

Direct standalone StreamingFillBackend callers that do not supply a staging policy retain their caller-owned behavior. Aggregate admission guarantees here concern the managed Executor path; a standalone script is not silently attached to a Machine authority.

CPU evidence covers real TensorFS single-slot streaming, delayed simulated DMA, exact geometry, constructor failure, copy-drain failure, reusable physical buffers, idle release without RSS credit, real rank subprocess plan agreement, asymmetric refusal, minimum operation host vectors, and first-construction garbage collection. These tests do not qualify GPU transfer ordering, pinned allocation behavior on a device, or multi-GPU throughput. No active environment install or device execution is part of this PR.

This prerequisite keeps ordinary admission policy: requesting the desired ring can reclaim eligible idle cache before the Planner reduces the slot count. The old fill allocated that desired ring without admission. Qualification must measure the new admitted ring against retained model residency. An optional asynchronous experiment must use already-owned capacity or separately decline surplus demand without reclaiming useful cache; this PR does not add an optional HostRoom wire field.
