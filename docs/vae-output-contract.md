# Actual H3 final output stage

This new edge uses the existing functional Torch LayerNorm allocation contract,
followed by a queried prepared dense projection and explicit pixel assembly.
It is additive; root owns outer sequence admission, shared block factoring and
package cutover. No nested split or Python byte/admission policy is introduced.

## Exact operation

For tile batch B, the release geometry is D/H/W=7/16/16, P=1792 patches and
T=P+4 register tokens+1 zero token=1797. Incoming final residual is contiguous
FP32 `[B,T,2048]`; affine norm scale and bias are contiguous FP32 `[2048]`.
Reject other geometry/dtype/configuration before writes. CUDA FP16 autocast is
required, with the existing dense provider's complete math policy.

`norm_out` is affine `nn.LayerNorm(2048, eps=1e-5)`. Pinned Torch
`08187d9e0fba026dc8217405802ab5381dc88d90` registers LayerNorm/native LayerNorm
under CUDA FP32 autocast. Already-FP32 inputs/parameters need no autocast copy.
The [CUDA forward implementation](https://github.com/pytorch/pytorch/blob/08187d9e0fba026dc8217405802ab5381dc88d90/aten/src/ATen/native/cuda/layer_norm_kernel.cu)
allocates contiguous output plus FP32 mean/rstd for each row. Its reviewed forward
kernel path uses CUDA shared memory and direct launches, with no additional global
tensor scratch. Contiguous/alignment checks avoid its input/parameter copy paths.

The public `.out` overload is not allocation-free:
[native_functions.yaml](https://github.com/pytorch/pytorch/blob/08187d9e0fba026dc8217405802ab5381dc88d90/aten/src/ATen/native/native_functions.yaml)
marks it autogenerated, and the
[generator](https://github.com/pytorch/pytorch/blob/08187d9e0fba026dc8217405802ab5381dc88d90/torchgen/native_function_generation.py)
calls the functional operator then copies all three results. Use the real functional
operator and declare its three allocations. Do not preallocate duplicate outputs.
The [autocast registration](https://github.com/pytorch/pytorch/blob/08187d9e0fba026dc8217405802ab5381dc88d90/aten/src/ATen/autocast_mode.h)
and pinned source hashes are part of this contract. Torch 2.15 is unsupported until
its corresponding allocation ABI is separately verified; decline before writes.

The actual `proj_out` is biased 2048->3072, with FP16 or FP32 matrix storage and
FP32 bias. Preserve all T rows through projection, then take the first P rows.
For FP16 matrix storage, package `.to(matrix.dtype)` performs the FP32->FP16 input
cast. For FP32 storage, that call is a view/no-op and linear autocast performs the
same FP32->FP16 input cast, plus a weight cast. The prepared route owns these casts
explicitly. Its shared Context queries the actual M=B*T, K=2048, N=3072 algorithm
and workspace before admission; no Conv3d or RMSNorm equivalence is asserted.

The prefix view reshapes to `[B,7,16,16,3,4,16,16]`, permutes axes
`(0,4,1,5,2,6,3,7)`, then copies directly into contiguous FP16
`[B,3,28,256,256]`. Prefix/reshape/permute are views, including the inter-batch gap
from the five discarded projection rows. The complete projection owner remains live
through the copy. Skipping the five rows before projection is a different schedule.

## Payloads and live intervals

Let M=B*1797 and Q=3072. Source tensors and the preceding residual are existing
holdings and must retain their owning Source through completion.

| Owned buffer | Bytes | Allocation/release boundary |
|---|---:|---|
| FP16 projection bias | 6144 | Actual query preparation; retain through completion/Plan retirement |
| FP16 projection input | 2*M*2048 | Preallocate after complete admission; retain through completion |
| Optional FP16 matrix cast | 2*3072*2048 | FP32 matrix only; retain through completion |
| Full FP16 projection result | 2*M*3072 | Preallocate after admission; keep all T rows through pixel copy |
| Contiguous pixel result | 2*B*1792*3072 | Preallocate after admission; returned owner survives handoff |
| Queried dense workspace | Actual query result | Preallocate after admission; retain through completion |
| Functional norm output | 4*M*2048 | Created by native LayerNorm inside accepted operation; retain through completion |
| Functional mean | 4*M | Created by native LayerNorm; retain through completion in this first implementation |
| Functional rstd | 4*M | Created by native LayerNorm; retain through completion in this first implementation |

The exact execution inventory includes both preallocated and functional allocations.
The three norm results intentionally survive until checked stream completion; the
native binding then releases them. This first version has no intra-operation buffer
reuse or assumed transient reclamation. Bias is an already-live preparation holding
and is counted once. Native/kernel implementation and CUDA allocation census still
need paired GPU proof; source closure alone is not GPU qualification.
