# Generic per-slot LoRA execution

The wire55 serving path binds an ordered adapter list to each model slot. Each entry selects one base component, an ordinary TensorFS adapter snapshot/component, and a finite decimal strength. The source converter owns ecosystem key normalization; no model-package LoRA loader is called. Unadapted bindings retain the wire44 floor and their previous canonical spelling.

Canonical tensors are `<module>.lora_A.weight` `[rank,input]`, `<module>.lora_B.weight` `[output,rank]`, and optional scalar `<module>.alpha` (default rank). Every key must be consumed. Runtime proves target containment against the selected component/base snapshot and constructed linear geometry, reads factors under ordinary verified TensorFS leases, scans finite values, and converts private copies to the compute dtype. Strengths are independent additive coefficients, including negative values. Zero strength still validates tensors and owns no factor allocations. Nonempty adapter configs/assets refuse until their inference-contract semantics are supported; training-task provenance alone does not establish or refute structural fit.

The construction identity contains the exact base/target geometry and adapter implementation digest. Different adapter payloads, ranks or strengths with the same target set can reuse that construction. Hooks are installed once, before fusion, and survive encoded-leaf restaging through Runtime's existing registry transfer. Active LoRAs require the original floating input; inactive hooks preserve the original fused FP8 activation path. Base parameters and encoded payloads never change.

Low-rank GEMMs run in 16,384-row tiles, including padded final tiles. Runtime first multiplies the private delta by its coefficient, then adds into the supported linear's fresh output, preserving separate compute-dtype multiply/add rounding. Hooks run before other local output hooks; wrapped/global/preceding hooks, aliases to input/base storage, unsupported module types and noncontiguous input/output layouts refuse. This avoids sequence-sized copies. Static scratch is bounded by `tile_rows * (input + rank + output) * compute_width`, independent of sequence length and stack count. Placement reserves all factor sets plus maximum tile scratch; every rank checks its actual available capacity before allocation.

Each attempt owns its CPU copies, device factors and leases. Cancellation/error cleanup clears references even if diagnostics retain an exception/context. Closed or poisoned bindings refuse reuse, including unadapted requests. Per-model `RequestView.adapters` reports the selected stack. Independent model slots may use the same base checkpoint with different stacks; aliases to one constructed root refuse before allocation. The leader opens the same exact stack on every Ulysses rank, verifies digests, includes that identity on mirrored calls, and closes every rank's scope after the attempt.

CPU tests cover real TensorFS reads, arithmetic, independent slots, cleanup, static admission and measured live tensor scratch. They do not qualify GPU behavior. Fixed GEMM shapes do not universally guarantee numerical identity: CPU FP32 partition tests showed small reduction differences; BF16 and actual H100 output require their own evidence. H100 1/2/4-GPU parity, peak memory, tile overhead, zero/no-adapter parity with H3 NumericalChecks and generated adapter quality remain qualification gates.

This change remains coordinated with worker-protocol87, Creator's adapter transport and Tensorhub's nested-download support. No partial wire rollout is valid. Ordinary CLI GPU qualification is pending, and model-free job adapter selections explicitly refuse rather than being silently dropped. No Runtime version bump or PyPI publication is introduced by this work.
